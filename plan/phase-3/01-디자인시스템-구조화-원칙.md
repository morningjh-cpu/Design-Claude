# 디자인시스템 구조화 원칙
목표: 기존 토큰과 컴포넌트는 유지하고, KRDS의 분류 체계와 문서 구조만 적용한다.

## 절대 변경 금지
- Variables의 이름, 값, 그룹 경로, 컬렉션, 모드 (생성·삭제·이동 포함)
- 컴포넌트와 컴포넌트 property의 이름
- 기존 variant 삭제나 구조 변경

## 허용
- 페이지, 섹션, 프레임 재배치와 정리
- 문서 프레임 추가 (사용 가이드, 매핑표)
- 누락된 상태나 variant의 추가 (기존 Variables만 사용)

## 작업 방식
- 수정 전 변경 계획을 표로 보고하고 승인받은 뒤 실행
- 금지 항목을 바꿔야 할 것 같으면 실행하지 말고 '제안'으로만 기록
