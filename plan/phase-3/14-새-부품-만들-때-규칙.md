# 14. 새 부품 만들 때 미리 지킬 규칙 (2026-11-17)

사용자: "제안대로 할게" — 원본 작업 전까지 새로 만드는 부품에 정해진 규칙을 미리 쓰기로 함.
원본 파일에서 부품을 만들 때 보는 한 장. 근거는 13번 문서 2번.

## 이름
- 같은 이름의 부품을 두 개 만들지 않는다. 쓰임이 다르면 앞에 쓰임을 붙인다(예: `chart-bubble`, `search-dropdown-list`).
- 철자를 확인한다. 테스트에서 고친 오타: txet · anlysis · aothor · leftt · folter.
- 임시 이름(`Component`, `Property 1`)으로 두지 않는다.
- 이름 앞뒤에 빈칸을 넣지 않는다.

## 종류 칸
- `name` 칸을 맨 앞에 둔다. 값은 부품 이름과 같게(빗금이 있으면 마지막 토막). 묶음마다 값 하나.
- 칸 이름은 `state` · `type` · `size` 로 쓴다. 테스트에서 고친 오타: stste · staet · stete · stae · namr · stichy.
- 종류가 여럿으로 갈리면 묶음을 새로 만들지 말고 `type` 값으로 나눈다(예: `service-tag` 의 `type=ipo`).

## 상태 순서
- 입력폼: default · hover · focused · typing · typed · disabled · error
- 뒤에 말이 붙은 상태(typing-open 등)는 원래 상태 바로 뒤. (AI 가 정함)
- 선택 쪽: … unchecked · unselected · checked · selected · active · partial, disabled · error 는 맨 뒤. (AI 가 정함)
- 기본 상태와 모습이 같아 default 를 안 만드는 묶음도 나머지는 같은 순서.

## 묶음 안 배치
- 가로 = 사이즈(xxs → xs → sm → md → lg), 세로 = state.
- type 이 있으면 type 별로 모아 둔다.

## 놓는 자리
- 6묶음 중 하나에 넣는다: 1. 일반 · 2. 틀 · 3. 탐색 · 4. 입력 · 5. 데이터 표시 · 6. 피드백.
- 원본은 아직 6묶음 구역이 없으니, 지금은 묶음을 정해 두기만 한다(어느 묶음인지 헷갈리면 03번 분류표 참고).

## 안 바꾸는 것
- 저장값(Variables) 이름 · 값 · 경로 · 모드.
- 이미 있는 부품의 이름·칸 이름은 원본 작업 2단계에서 한꺼번에(개발 쪽과 날짜 맞춰).
