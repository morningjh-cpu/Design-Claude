# 15 commit-commands — 저장(커밋)·올리기를 명령 한 번에

**쓰는 일:** 개발 ●  (디자인·기획 폴더도 버전 저장용으로 사용 가능)

커밋: 지금까지 바뀐 파일을 하나의 "저장 지점"으로 기록하는 것. 나중에 그 시점으로 되돌릴 수 있음.

## 명령어
| 명령 | 하는 일 | 언제 |
|---|---|---|
| `/commit-commands:commit` | 바뀐 내용을 보고 설명을 붙여 커밋 1개 만들기 | 작업 한 덩어리가 끝났을 때 |
| `/commit-commands:commit-push-pr` | (main이면 새 갈래 만들고) 커밋 → 깃허브에 올리기 → 검토 요청(PR) 만들기 | 동료에게 검토받을 때 |
| `/commit-commands:clean_gone` | 깃허브에서 이미 지워진 갈래(브랜치)를 내 컴퓨터에서도 정리 | 갈래가 쌓여 지저분할 때 |

- PR(풀 리퀘스트): "이 변경을 합쳐도 될지 봐 주세요" 요청
- 브랜치(갈래): 원본을 건드리지 않고 따로 작업하는 줄기

## 사용자 규칙과의 관계
- 커밋은 "cmt"라고 할 때만 함 → **이 명령을 직접 입력하는 것도 "cmt"와 같은 승인으로 봄**
- 저절로 실행되지 않음. 직접 칠 때만 움직임

## 주의
- commit-push-pr은 깃허브에 올리고 PR까지 만듦(바깥으로 공개) → 올려도 되는 내용인지 먼저 확인
- 이 폴더는 아직 깃허브에 올린(push) 적 없음 — 첫 push 전 개인정보·내부 자료(data/) 포함 여부 확인 권장
- clean_gone은 갈래를 지움(되돌리기 어려움) → 쓰기 전 목록을 먼저 보여 달라고 하기
- 커밋 설명이 영어로 써질 수 있음 → "한국어로"라고 덧붙이기
